# SOOYA-IPA 收口状态（2026-08-14）

这份文档记录最终落地方案在当前仓库内已经落地的部分，以及不能由仓库代码单独完成的剩余验收项。方案原文仍是同一分支中的 `docs/SOOYA-IPA-main940f8102-最终落地方案-含Ombre优先双向同步.md`。

## 已在仓库内完成

- Native Base / bridge 3、只读 Native Release Config、Ed25519 OTA pinned public key。
- OTA 校验、native/schema/capability gate、pending/last-good、坏包 fail-closed/rollback 状态。
- OTA workflow：构建只强制签名私钥；正式 publish 强制 URL、token、私钥；当前 schema gate 为 46。
- LocalCore、SQLite、MCP、Provider、Memory、Life/Moment、Admin bridge 与 unsigned IPA workflow。
- Ombre/Local Memory 基础双向同步：
  - Ombre MCP 在线优先 recall，Local recall 并行补充并统一去重。
  - Local 先落盘，之后通过 durable outbox 异步 push。
  - Ombre delta/cursor pull；旧 schema 无 delta 时使用 catalog fallback。
  - sourceId/sourceHash/normalized 去重，Ombre 版本优先。
  - update/forget 通过 sync state、tombstone 和重试队列传播。
  - Ombre timeout、401、断线、工具缺失时自动降级到 Local；连续失败触发短暂 circuit breaker。
  - 未配置本地 `ombre` MCP server 时不连接远程，默认仍是纯本地。
- Admin Memory 状态增加同步统计与“立即同步”入口。
- 方案和 `HANDOFF.md` 与本状态文档均在同一分支。

## 不能伪造为已完成的项目

这些项目需要真实权限、真实设备、真实服务或用户操作，当前没有被本地代码测试替代：

1. 合并 PR3 到 `main`。
2. 在 GitHub Actions Secrets 配置：
   - `OTA_PRIVATE_KEY`
   - `OTA_PUBLISH_URL`
   - `OTA_PUBLISH_TOKEN`
3. 使用用户自己的签名证书生成正式 IPA，并在真机完成一次安装。
4. 真机 Native Self-Test、正常 OTA、签名错误/哈希错误/兼容性错误、自动 rollback、断网与恢复验收。
5. 从 `sooya7/sooya` 导出真实 DB snapshot、media、config 和 Ombre memory，导入真机并核对：
   - messages/moments/stickers 数量
   - media SHA256
   - `integrity_check=ok`
   - `foreign_key_check=0`
   - Keychain secret ref 未泄漏
6. 将本机 MCP server 配置为真实 id=`ombre` 的 Ombre endpoint，验证真实 catalog/delta、push/pull、edit/forget、conflict 与恢复收敛。
7. 真机验收完成后，才执行旧服务器和 Ombre runtime 停机；服务器仓库 `sooya7/sooya` 的 `main` 不在本仓库任务范围内。

# SOOYA 服务器版 → IPA 全本地版功能迁移对比

> 审计日期：2026-08-14  
> 服务器版：`sooya7/sooya@main`  
> IPA 版基线：`sooya7/sooya-ipa@011f82b`  
> 本次修复分支：`fix/native-contract-parity-0814`

## 结论

**目前还没有做到服务器版功能 100% 迁移。**

IPA 已经具备完整的本地应用骨架：本地 SQLite、LocalCore、连续聊天、消息历史、基础上下文、Life/位置/天气、动态、媒体存储、Ombre/本地记忆、MCP Host、Tool Runtime、Admin、备份和 OTA 都有对应实现。

但服务器版最关键的“多模态表达链”和“主动能力链”还存在明显缺口，尤其是：

1. Media Director 尚未迁移。
2. Vision 尚未真正进入回复链。
3. 图片生成 Provider 有配置和实现，但没有接进可见回复链。
4. TTS Provider 有配置和实现，但没有接进可见回复链。
5. Web Search 在本地 Admin 中明确返回“未启用”。
6. 表情包 AI 分析接口目前是占位返回，不会实际分析。
7. 用户/模型媒体指令协议未迁入 Local ReplyCoordinator。
8. Proactive 主动聊天明确关闭，本地通知当前只做能力探测，不负责主动消息调度。
9. MCP 基础 Host 已迁移，但服务器版的自动重连、required/best-effort 等完整运行时语义仍需继续对齐。
10. 服务器版的媒体文本提取、变体处理、完整媒体备份/存储治理仍是部分迁移。

所以目前状态更准确地说是：**核心本地化完成，多模态与主动链路未完全收口。**

# A. 本次 Native Bridge 修复

本轮不是继续给真机报错逐个打补丁，而是统一修复 TypeScript ↔ Capacitor ↔ Swift 的契约。

## A1. SQLite Bridge

已修：

- `query()` 正确解包 Swift 的 `{ columns, rows }`，返回 Core 需要的 `T[]`。
- `run()` 将 Swift `lastInsertRowId` 映射为 Core 的 `lastInsertRowid`。
- `integrity()` 将 Swift `messages / foreignKeyViolations` 映射为 Core `integrity / foreignKeys`。
- Transaction 保留 `execute / run / query` 类型，Swift 不再把所有操作都当 `run`。
- `execute` transaction 支持迁移脚本中的多 SQL statement。
- `Uint8Array / ArrayBuffer` 通过 `{ type: "blob", base64 }` 跨 Bridge。
- `bigint` 通过 `{ type: "int64", value }` 跨 Bridge，避免 JS Safe Integer 精度丢失。
- Swift 查询返回超出 JS Safe Integer 的整数时也使用 tagged int64 回传。

这部分是启动数据库迁移能否在真机真正跑起来的关键修复。

## A2. Media Bridge

已修：

- TS 保存媒体改传 Swift 真正读取的 `mimeType`。
- TS `read()` 改为消费 Swift 实际返回的 `{ metadata, dataBase64 }`。
- TS 删除媒体改读 Swift 的 `{ deleted }`。
- 原生 sidecar 增加可选 `kind`，保留 `sticker / image / audio / file` 类型。
- `kind` 为 optional，兼容旧 Base 已经写出的 sidecar。

这部分直接影响真实头像、用户图片、表情包和本地媒体恢复。

## A3. Keychain

已移除伪造的：

```text
TEAMID.com.sooya.app
```

fallback。

现在如果签名后的真实 Keychain Access Group 无法解析，会明确失败，不再用一个必然可能与重签名 Team ID 不匹配的假组继续运行。

涉及：

- `SOOYASecretsPlugin`
- `SOOYAHttpPlugin` 的 API Key 读取
- `SOOYAMcpPlugin` 的 Token 读取

## A4. Native 启动容错

本地核心成功安装后：

- OTA 初始化失败不再让整个 App 显示“本地核心启动失败”。
- App/Keyboard lifecycle bridge 失败也不再阻断聊天、动态、Admin。
- 内置表情包 seed 不再强依赖 OTA updater 存在。

也就是说“聊天本地核心”与“OTA/辅助能力”已经拆开故障域。

## A5. Native Base

因为本轮修改了 Swift 原生 Bridge：

```text
Native Base: 6 → 7
Bridge Version: 3 → 4
```

OTA workflow 同步改为：

```text
native-min 7
native-max 7
```

Base 6 不会误吃 Base 7 的 OTA Web Bundle。

# C. 为什么之前看起来“几乎都迁了”

IPA 现在有大量服务器版相同的：

- 数据表
- Repo
- Admin 页面
- Provider 类型
- 配置字段
- API-shaped `adminRequest()`

所以从 UI 或 schema 看，很容易误判为功能已经完整迁移。

但真正决定“能不能用”的是 **runtime wiring**。

例如：

```text
Image Provider 已存在
≠
聊天时会根据用户意图触发生图

TTS Provider 已存在
≠
回复能生成并发送语音 part

media_text 表已存在
≠
图片/文件已经自动做文本提取

Vision API Key 字段存在
≠
用户发图片时模型真的收到图片
```

本次对比重点就是把“存在结构”和“真正接通运行链”分开。

# D. 必须继续迁移的 P0 功能

如果目标仍然是：**关掉 SOOYA 业务服务器后，手机上的 SOOYA 与服务器版核心体验等价**，下一阶段至少要一次补齐下面 6 条链。

## P0-1 Media Director

迁移服务器版：

```text
packages/server/src/core/director/*
packages/server/src/core/mediaDirector.ts
```

改造成纯 TS Core：

```text
packages/core/src/director/*
packages/core/src/media/media-director.ts
```

负责：

- sticker 决策
- voice 决策/口语化
- image prompt 扩写
- media failure fallback

## P0-2 Directives

迁移服务器版：

```text
packages/server/src/core/directives.ts
```

并接入 Local ReplyCoordinator：

```text
用户文本
→ parseUserDirectives
→ Reply
→ parse model media markers
→ Media Director
→ media parts
```

否则用户说“给我发个自拍”“用语音说”“换个表情”时，本地版不会达到服务器版行为。

## P0-3 Vision

当前 Local ReplyCoordinator 的 `buildTurns()` 只提取文字。

需要把消息中的：

```text
image part
media id
mime
binary
```

通过本地 MediaPlatform 读出并转换为 `ChatImagePart`，同时增加独立 Vision 配置或与服务器版相同的 Vision fallback 策略。

## P0-4 Image + TTS 真正接入回复

Provider 已经有，缺的是业务编排：

```text
reply text
→ Media Director
→ ImageProvider / TtsProvider
→ Native Media Store
→ media row
→ assistant MessagePart(image/audio)
→ event
→ UI
```

## P0-5 Web Search

迁移服务器：

```text
packages/server/src/core/web-search/*
```

保留 provider isolation / policy，底层请求改走 Native HTTP。

不能只把 `ChatRequest.webSearch` 类型留在 Core，而没有 service/runtime。

## P0-6 Sticker AI

迁移服务器：

```text
packages/server/src/core/stickers/analyzer.ts
packages/server/src/core/stickers/retriever.ts
packages/server/src/core/stickers/picker.ts
packages/server/src/core/stickers/semantic-text.ts
packages/server/src/core/stickers/user-meaning.ts
```

让 Admin 的：

```text
analyze
analyze-batch
```

从 placeholder 变成真任务，并让 assistant 回复链真正用 picker 选表情。

# F. 主动消息要不要迁移

这里需要区分“之前迁移方案的明确决定”和“服务器版功能一致性”。

旧迁移方案曾明确写：

```text
不做主动聊天消息
不做 APNs
不做 Web Push
不做本地通知业务调度
```

当前代码也延续了这个决定：

- Life Admin `reachOut=false`
- `proactiveMode='disabled'`
- 本地通知只做 capability probe
- remote push 固定关闭

所以从“原迁移方案”角度它不是遗漏，而是**明确裁掉的服务器功能**。

但如果现在的验收标准改为“服务器版功能都必须迁到 IPA”，那它就必须重新列入迁移范围，并按 iOS 的运行限制重新设计，而不能照搬 Linux 常驻 worker。

建议的 iOS 等价方式：

```text
Life / Thought / Moment 状态
        ↓
前台 catch-up + BGTask 可用时补算
        ↓
符合 reach-out 条件
        ↓
Local Notification
        ↓
用户打开 App 后恢复/生成对应主动消息
```

这样不依赖 SOOYA 业务服务器，也不会伪装成 iOS 上不存在的常驻 Node worker。

# G. 当前验收结论

## 本轮修复后的目标

Native Base 7 应先满足：

- App 能完成 SQLite open + migration。
- LocalCore 能成功安装。
- 聊天页、动态、Admin 都使用同一个 LocalSooyaClient。
- 真实头像/媒体可从 Native Media Bridge 读取。
- OTA 故障不会拖死 LocalCore。
- BLOB / bigint 不会在 Bridge 上损坏。
- Keychain 不再使用假 Team ID。

## 但不能把 Base 7 称为“服务器功能 100% 迁移完成版”

更准确的版本定位：

> **Base 7 = Native LocalCore 基础链路收口版。**
>
> 下一阶段仍需完成 Media Director / Vision / Image / TTS / Web Search / Sticker AI 等服务器功能的运行时迁移，之后才适合宣告“服务器业务可以完全下线且功能等价”。

---

# H. 建议的完成标准

最终“全部迁移完成”不能只看 CI 绿灯，至少要求真机 E2E 覆盖：

1. 纯文字聊天。
2. 连续快速发送触发 revision fencing。
3. 发图片，SOOYA 能看懂图片内容。
4. “发个表情”，能自动选并发送正确表情。
5. “给我拍张自拍”，能走 reference image 生图。
6. “用语音说”，能生成 audio part 并播放。
7. 需要最新信息的问题能实际执行 Web Search。
8. Ombre 读、写、同步、断线恢复。
9. MCP tool discover / authorize / invoke / reconnect。
10. Life 前后台切换和 catch-up。
11. 主动消息（如果重新纳入范围）。
12. 数据库 + Media 完整备份、恢复。
13. OTA 成功、失败回滚、旧 Base gate。
14. 重签名覆盖安装后 Keychain/数据仍可用。

只有上述链路跑通，才建议把“服务器版功能已全部迁移”标记为完成。
